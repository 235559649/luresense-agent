# 人工证据评分规范 v1

评估对象是“给定资料是否支持回答，以及是否正确处理条件”。不是实地鱼情真值。先固定同一模型和知识版本，再比较流程。

## 每条主张 support

| 值 | 使用条件 |
| --- | --- |
| pending | 尚未评审，默认值 |
| supported | 所引用资料支持主张全部关键内容、强度和适用条件；推断明确标注且合理、限制充分 |
| partial | 支持部分内容，但有范围扩大、必要条件遗漏或措辞增强 |
| unsupported | 核心结论没有依据或与证据矛盾；不得仅因引用编号存在判支持 |
| unresolved | 来源含混、资料冲突或需要领域专家，评审无法确定 |

每个非pending标签必须填写note，说明哪个片段支持或不支持哪个词句。一个复合句有支持和不支持的部分，应记录partial或核心不支持时unsupported，不因开头正确就全判支持。

示例：卡片说“水温影响活动”，回答说“水温影响活动，因此任何情形都必须精确测温”。可标partial，并指出“任何情形”“必须精确”未获支持。不是要求所有评审无条件采用这一标签，应按整条主张核心与完整证据判断。

## 回答级字段

统一使用pending/yes/no/unknown。

- answerable：给定当前知识及当前用户条件，是否存在可支持的实质回答？可回答一部分也可yes，但note需说明范围。
- useful：是否实际提供了对当前问题有用且有支持的内容？纯粹堆来源、全拒答或重复问题不能自动yes。
- condition_correct：是否保留未知、尊重最新修改、区分气温与水温、没有把用户自述当作实测？没有条件处理任务时填unknown并解释不适用。
- abstention_appropriate：确实拒答时，拒答是否必要且理由合适？正常回答时填unknown并在note注明不适用；接口失败不等于合理拒答。

请填写reviewer并记录评分理由。评审者可能有偏差；对争议条目保留unresolved，找同学核对来源或请领域专家复核。

## 如何读汇总

先看所有状态计数和真实条目数，再看评分覆盖率，再看主张支持与有效回答。不能只展示不支持率下降，而隐藏拒答、失败增加或覆盖率变低。

unsupported_rate_among_decided = unsupported / (supported + partial + unsupported)

not_fully_supported_rate_among_decided = (partial + unsupported) / (supported + partial + unsupported)

decided_coverage = (supported + partial + unsupported) / 全部主张数量

没有已决主张时比例是null。所有答案都拒答时“没有不支持主张”不等于优秀系统。汇总不会自动给出总分或“准确率”。

## 一组可管理的实验

先做相同5～10题的开发对照：旧固定RAG、给同等完整条件的旧RAG、新条件流程。保留全部结果，记录调用预算、拒答和失败。

第三版同时改变提示词、检索查询构建和输出结构，因此初步比较反映整个系统变化，不应声称已经分离某一机制的因果作用。后续固定其它部分，只打开/关闭澄清或证据约束，才是对应消融。
