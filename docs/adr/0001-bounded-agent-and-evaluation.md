# ADR-0001：有界工作流与分层评估

状态：记录当前实现。适用范围：个人维护、面向求职展示的 LureSense。

## 问题

输入可能只有“应该先看哪里”，现有知识来源有限，项目没有照片、传感器与现场鱼类标签。如果让模型补齐所有条件，回答流畅也可能无法追溯；如果一开始加入多个 Agent、数据库和工具协议，维护成本会超过当前验证能力。

## 决策

保留显式 ContextSession：槽位区分 unanswered、unknown、user_reported；用户描述始终不是现场验证。最多自动追问两项，每会话最多三次模型请求。相同状态用于后端、CLI 和 Web。

知识卡保存来源与适用限制；模型回答按来源事实和项目推断区分。结构校验、引用存在校验和人工语义审查各司其职。模型不控制追问轮数，不从自由文本直接执行命令或外部操作。

评估分两层：无 API 的检索/状态实验用于快速回归；真实模型加人工评审用于回答质量。工程单元测试用于验证程序契约，不冒充研究实验结果。

## 对比过的替代方案

| 方案 | 优点 | 当前不优先采用的原因 / 启用条件 |
| --- | --- | --- |
| 单轮检索 + 生成 | 简单、可作为基线 | 模糊信息和条件修正处理不足，已保留用于对照 |
| LLM 自主规划所有流程 | 表达灵活 | 难约束轮数、成本和未知条件；有可靠评估与复杂工具任务后再考虑 |
| 多 Agent 分工 | 适合独立任务协作 | 当前流程较短，额外通信不能自然带来可测收益 |
| 向量检索/混合检索 | 可改善同义表达召回 | 当前22张卡先量化关键词缺陷；有独立案例再比较，引入依赖须有指标收益 |
| 长期记忆/数据库 | 可保存跨会话记录 | 当前明确导出 JSON 即可满足审查；有多次真实使用需求再添加 |

## 代价与已知不足

规则词表不是通用自然语言理解，含“海边”的否定句可能被误判范围外。最多两项追问会遗漏某些条件。自动摘录匹配不能证明语义支持。每会话预算不是全局费用预算。Web 为本机演示，内存状态不会长期保存。

## 如何推翻本决策

若固定、独立编写的案例表明规则路由造成系统性错误，而更灵活方法能在相同成本约束下提高条件一致性，新增对比实验后替换该模块。若知识库扩展并出现大量语义漏检，再加入混合检索作为新实验组。按测得的问题演进，不以组件数量判断完成度。
