# 实验设计：检索与状态控制是否带来可观察差异

## 研究问题与范围

RQ1：模糊问题获得补充条件后，相关知识卡是否更容易被召回？

RQ2：用户修正条件、明确未知或使用否定表达时，状态驱动查询是否比直接拼接保留更少失效词？

RQ3：系统在哪些语言表达与召回场景下仍失败？

当前实验只运行检索与规则状态机，完全不请求模型。它验证的是模块行为，不是建议质量、实际鱼情识别或现场有效性。已有的真实模型记录及人工评估工具承担回答层验证；两层指标不能混算。

## 三个实验组

| 组 | 输入 | 执行 | 用途与限制 |
| --- | --- | --- | --- |
| direct | 用户原始问题 | 原有 KnowledgeBase.search | 对应最简单的单轮检索；没有追问得到的信息 |
| append_context | 原始问题 + 同一会话的最终条件文本 | 同一检索器 | 同信息条件下的简单拼接基线，但原句旧信息仍在，字段名也可能影响匹配 |
| agent_state | 原问题经规则分类 + 最终显式状态 | 原有 respond(mock) | 按最新状态构造检索词，有界追问与未知状态门控 |

三组知识库、检索器和 top-k=4 相同。direct 与其他两组信息量不同，不能声称差异完全来自算法。后两组条件来自同一规则状态机，append_context 不是独立实现的产品；它只隔离“文本拼接与状态查询”这一实现选择的一部分。

修正案例只计最终状态，每个情景每组一条结果，不把多轮交互当作多个独立样本。覆盖多轮历史的正确性另由既有测试保障。

## 数据与标注

共 30 条人工构造情景，20 条 dev、10 条 challenge。类别包含知识、模糊请求、未知、条件修正、范围外、无匹配知识、温度来源、否定与否定范围。分组便于管理工作流程；案例由同一作者结合已知规则和知识库设计，有模板重叠，challenge 不称为独立测试集或未见数据。

标注状态为 `draft_author_labels_not_expert_validated`，你应逐条复核：

- `answers`：追问时给出的选项编号。必须提供被询问槽位；脚本不自动补为“不知道”。
- `corrections`：澄清结束后依次应用的显式修正。
- `relevant_ids`：预期相关的卡片集合，来自现有知识卡，不是网页原文标注或鱼情标签。集合不保证穷尽。
- `expect_no_evidence`：本项目在该情景下预期停止现场证据输出的案例；与“所有世界知识都无法回答”不同。
- `expected_context`：需要核对的最终槽位。null 必须对应明确未知，不能是尚未询问。
- `forbidden_query_terms`：修正/否定后不应继续用于检索的旧词；仅检查查询文本，不禁止文档谈论该词。

预期相关卡并不等同于足以回答整个问题。后续若要评估“有鱼吗”这类具体结论是否被模型恰当地拒答，必须增加回答级标注并真实调用模型。

## 指标定义

设一个适用情景的标注相关卡为 R，top-4 结果为 L。

- Hit@4：R 与 L 有交集则为 1，否则 0。
- Recall@4：|R ∩ L| / |R|。
- MRR@4：第一个相关卡的排名倒数；没命中记 0，再对相关卡非空的情景取平均。
- 负例空检索率：预期不输出现场证据的情景中，检索为空的比例。这不是 LLM 拒答准确率。
- 失效词移除率：带 forbidden_query_terms 的情景中，查询不含任何失效词的比例。
- 状态匹配率：对有上下文标注的 agent_state 情景，所有已标注槽位值匹配且不是 unanswered 的比例。

每项输出适用分母 n；n=0 用 null/横线表示，不能填 0 或 100%。基线无状态，因此状态指标不适用。没有穷尽相关集，不计算 Precision；人工案例太少，不报告显著性。

## 可复现与审查

运行记录包含数据快照、数据/知识/来源/核心代码 SHA-256、Python 版本、时间、每组查询、召回 ID、逐案例指标与分组汇总。输出目录必须不存在，避免覆盖旧实验。系统错误停止执行；低分与行为失败正常写入报告，不会被脚本过滤掉。

若中断留下不完整目录，保留它并换新目录重跑；当前不实现断点续跑。使用同一代码和数据，指标应相同；运行时间戳不同是正常的。

每个 agent_runs/Sxx.json 是 mock 会话记录，可由 review_runs.py 读取，但不会成为真实模型质量样本。切勿把本离线报告中的命中率写成 LLM 准确率。

## 从本轮结果到下一轮改进

1. 先逐条核对相关卡标注，固定本轮数据和代码版本。
2. 在 dev 上处理词形/别名遗漏与范围判断；每项修复附独立回归测试。
3. 保留当前报告作为基线，新输出目录生成后续报告，不回写旧结果。
4. 独立编写新增自然语言案例，交由熟悉钓鱼的人复核，减少自测偏差。
5. 再用固定模型运行小规模真实回答评估，人工审查条件一致性、证据支持和拒答适当性；报告请求错误及实际 token，不补造性能指标。
