所有场景是开发用假设，不是现场事实。先用mock确认流程，再选少量rag检查模型。固定模型、知识版本和参数，失败记录也保留。下表的预期是验收目标，不是预先声称大模型已经达到。

## 真实模型的首轮最小验收

1. 跑S02，保存记录。
2. 用/cover改为5，再生成一次，比较修改前后答案。
3. /exit保存；查看两个response事件的current_context是否不同。
4. 对每条主张记录：支持 / 部分支持 / 不支持 / 未决，并注明对应来源位置。
5. 如果模型仍沿用旧条件或夸大证据，记录原话，不把提示词里的要求当成已实现保证。

首次不用运行全部场景和大量重复调用。至少确认一条成功回答、一次纠正、一次资料不足，然后决定下一步改进。

## 与第二版的公平对照

保持原app.py不变，分别运行：

- B：第二版原始模糊问题。
- B+：第二版直接给完整假设条件“我在湖泊，看到水草和倒木，应该先看哪里？”。
- C：本步从模糊问题开始，经固定选择补全相同条件。

比较证据支持、有效回答、交互次数和成本。C与B的差异包含信息增加；C与B+还包含检索查询构建与提示词变化，本轮不能把所有改善归因于单一机制。后续消融需控制这些因素。
